# hateeze — твикер Windows для игр. Спецификация v1

Дата: 2026-10-26. Статус: черновик на ревью. Решения по расхождениям с исследованиями — `docs/DECISIONS.md`.

## 1. Цель и критерии успеха

**Что строим.** Настольное приложение для Windows 10/11 (аналог LatencyLens by SKID) со своим дизайном в стиле liquid glass и названием **hateeze**. Оно:
1. показывает задержки системы (DPC/ISR драйверов, таймер, прерывания) и даёт сравнить «до/после»;
2. применяет твики для игр с честной оценкой эффекта и безопасным откатом;
3. ставит драйверы (NVIDIA, AMD Radeon, чипсет AMD) с выбором компонентов, как NVCleanstall;
4. ставит игровые приложения и браузеры в один клик.

**Критерии успеха.**
- Каждый твик в основных разделах помечен как «проверено» или «по ситуации», и у этой оценки есть источник. Спорные твики собраны только в разделе «Эксперимент».
- Любое изменение откатывается: по одному, все сразу и горячей клавишей Ctrl+Alt+Shift+R. Перед первым изменением создаются снимок и точка восстановления.
- Установщик NVIDIA находит драйвер под установленную видеокарту, умеет вырезать телеметрию и NVIDIA App и ставит тихо.
- Программа — один `.exe`, работает офлайн (кроме загрузок) и не требует установки .NET.
- Интерфейс на русском, в стиле утверждённого макета `design/mockup-overview.html`.

**Что сказал пользователь / что допущено.**
- Сказал: аналог LatencyLens; дизайн liquid glass; имя hateeze; установщик драйверов NVIDIA/AMD «с поиском и отключением разных функций при установке»; установка Discord, ExitLag, FACEIT AC, Valorant, браузеров; «важные твики, которые 100% будут работать».
- Выбрал: стек C# + WebView2; проверенные твики + раздел «Эксперимент»; только русский язык; в первую версию — пресеты, чистое удаление драйвера (DDU), автообновление через GitHub, бенчмарк до/после.
- Допущено: только x64; поддержка Windows 10 22H2 и Windows 11 23H2/24H2/25H2; приложение всегда работает от администратора; собственной телеметрии нет.

## 2. Архитектура

```
hateeze.exe  (.NET 10, win-x64, self-contained single-file, requireAdministrator)
 ├─ Hateeze.App      — окно WinForms без рамки + WebView2 на весь размер, мост JS↔C#, горячая клавиша, трей нет
 ├─ Hateeze.Core     — вся логика: движок твиков, каталог, журнал/снимки, функции разделов, P/Invoke, загрузчики
 └─ web/dist         — интерфейс (Vite + Svelte 5 + TypeScript), встроен в exe как ресурсы и отдаётся с https://app.hateeze.example/
```

- **Почему так.** Чтобы стекло с размытием и преломлением выглядело правильно, интерфейс рисуется в WebView2 (Chromium) средствами CSS. Вся работа с системой — на C# с прямым доступом к Win32/ETW/NVAPI. WebView2 Runtime встроен в Windows 11. На Windows 10 без Runtime приложение предлагает поставить Evergreen Bootstrapper.
- **Слои Core.** `Interop/` (P/Invoke: advapi32, powrprof, setupapi/cfgmgr32, ntdll, pdh, kernel32, nvapi64) → `Platform/` (абстракции IRegistry, IServiceManager, ITaskScheduler, IPowerApi, IBcdEditor, IDeviceManager, IProcessRunner, IFileSystem, IHttp + реальные реализации) → `Engine/` (каталог, выполнение действий, журнал, снимки, откат) → `Features/<Раздел>/` (логика раздела + обработчики RPC).
- **Тестируемость.** Движок и функции зависят только от абстракций `Platform/`. В тестах вместо них работают поддельные реализации в памяти. На машине разработчика тесты ничего не меняют.
- **Где хранятся данные.** `%ProgramData%\hateeze\`: `baseline.json` (исходный снимок), `journal.jsonl` (журнал изменений), `settings.json`, `presets\`, `benchmarks\`, `downloads\` (кэш загрузок), `logs\`. Профиль WebView2 лежит в `%LOCALAPPDATA%\hateeze\WebView2`.

### 2.1 Структура репозитория

```
hateeze/
  hateeze.sln
  src/Hateeze.App/            Program.cs, MainForm.cs, Bridge/, app.manifest, hateeze.ico
  src/Hateeze.Core/           Interop/, Platform/, Engine/, Features/<Feature>/, Catalog/*.json (EmbeddedResource)
  tests/Hateeze.Core.Tests/   xUnit; Fakes/ — поддельные платформенные сервисы
  web/                        Vite + Svelte 5 + TypeScript; src/app/, src/ui/ (дизайн-система), src/pages/<feature>/, src/api/
  docs/                       research/, superpowers/specs, superpowers/plans
  design/                     утверждённые макеты
  build.ps1                   сборка web → копирование в ресурсы → dotnet publish
```

**Правило расширяемости, без общих файлов-реестров.** Функция C# — это класс `: IFeatureModule` в `Features/<X>/`, его находит сканирование сборки при старте. Страница интерфейса — папка `web/src/pages/<x>/` с `meta.ts` (id, название, группа меню, иконка, порядок) и компонентом `Page.svelte`; её подхватывает `import.meta.glob`. Новый раздел не требует правок чужих файлов. Это позволяет нескольким разработчикам работать параллельно без конфликтов.

## 3. Мост интерфейс ↔ ядро

- Транспорт: `window.chrome.webview.postMessage` ↔ `WebMessageReceived` / `PostWebMessageAsJson`.
- Запрос: `{ "id": 17, "method": "tweaks.apply", "params": {...} }`. Ответ: `{ "id": 17, "result": ... }` или `{ "id": 17, "error": { "code": "E_ACCESS", "message": "…по-русски…", "details": "…" } }`.
- События ядра: `{ "event": "monitor.tick", "data": {...} }`. Подписка явная: `monitor.subscribe` / `monitor.unsubscribe`.
- Долгие операции (загрузка и установка драйвера, очистка, бенчмарк) возвращают `operationId`. Ход идёт событиями `op.progress {operationId, stage, percent, message}` и завершается `op.done {operationId, ok, result|error}`. Отмена — `op.cancel`.
- Сериализация — System.Text.Json с source generators, camelCase. Контракты лежат в `Hateeze.Core/Contracts/*.cs` и зеркально в `web/src/api/types.ts`.
- В режиме разработки (`npm run dev` в браузере) мост заменяется на `web/src/api/mock.ts` с правдоподобными данными. Так весь интерфейс можно проверять без exe.
- Обработчики помечаются `[Rpc("tweaks.apply")]` внутри `IFeatureModule`. Исключения превращаются в `error` с русским текстом; полный стек пишется в `logs/`.

## 4. Движок твиков

### 4.1 Каталог
Твики описаны JSON-файлами `Catalog/*.tweaks.json`. Формат — `docs/catalog-format-v1.md`, проверка — `tools/catalog/validate.mjs`:
`id, category, title, description, recommendation, evidence (proven|situational|experimental|avoid), evidenceNote, risk (low|medium|high), riskNote, reboot (none|explorer|logoff|reboot), os, osNote, vendor, kind (toggle|value|select|info), options, apply[], revert[], detect, sources[]`.

- `info` — карточка-рекомендация без действий (BIOS, особенности CPU).

- `avoid`-записи в интерфейс не попадают. Они нужны, чтобы тест каталога не дал случайно добавить вредный твик под тем же ключом реестра.
- `experimental` показываются только в разделе «Эксперимент», с баннером «эффект не доказан».
- Действия (Action): `reg`, `bcd`, `service`, `task`, `power`, `nic`, `nvdrs`, `powershell` (крайний случай), а также динамические действия разделов: `msi`, `affinity` (по устройству), `ifeo` (по exe), `powerScheme`.

### 4.2 Применение
1. **Снимок (один раз).** Перед первым изменением на этой установке Windows:
   - создаётся точка восстановления. Если защита системы выключена, пользователю предлагают включить её на C:. Если Windows отказала из-за лимита «раз в 24 часа», это фиксируется и показывается;
   - сохраняются исходные значения всех целей каталога в `baseline.json`.
2. **Журнал.** Для каждого действия текущее значение «до» читается и пишется в `journal.jsonl`, затем действие выполняется, затем значение «после» проверяется чтением. Если после не совпало, это ошибка, и действия этого твика откатываются.
3. **Определение состояния.** Твик считается применённым, если все его `apply`-действия совпадают с текущим состоянием (или по `detect`). Состояние обновляется при каждом открытии раздела.
4. **Перезагрузка.** Твики с `reboot` ставят флаг «нужна перезагрузка». Вверху окна появляется баннер с кнопкой перезагрузки.

### 4.3 Откат
- **Один твик.** Каждая его цель возвращается к значению из `baseline.json` — то есть к состоянию до первого касания hateeze. Если цели в baseline нет, используется `revert` из каталога (дефолты Windows).
- **«Вернуть всё».** Каждая цель, которая встречалась в журнале, возвращается к baseline в порядке, обратном первому касанию. Затем показывается итог по каждому пункту.
- **Ctrl+Alt+Shift+R** (глобальная клавиша, работает при открытом приложении). Срабатывает при двойном нажатии за 3 с. Показывает 10-секундный отсчёт с кнопкой отмены, затем выполняет «Вернуть всё» и перезагружает компьютер. Если откат прошёл с ошибками, перезагрузки нет — показывается итог.
- Журнал не удаляется. Откат добавляет в него свои записи.

### 4.4 Безопасность
- **Запрещённые цели:** службы и драйверы античитов (vgc, vgk, FACEIT, EasyAntiCheat, BEService), критичные службы Windows (список из исследования). Движок отказывается выполнять над ними действия, даже если они попали в каталог или пресет.
- **Двойное подтверждение с объяснением риска** — для `risk: high`: MSI для контроллеров дисков, отключение VBS/HVCI, idle disable, отключение mitigations.
- **PowerShell-действия** выполняются только из каталога, вшитого в exe. Из импортированных пресетов принимаются только ссылки на `id` твиков и параметры динамических действий, без произвольных скриптов.

## 5. Разделы интерфейса

**Минимум текста.** Пользователь просил не писать лишнего. Подписи — одно-два слова. Строка твика показывает только название, чип оценки и переключатель; описание, «для игр», риск и источники открываются по клику на строку. Никаких служебных индикаторов («Администратор», подсказок про горячие клавиши) в интерфейсе нет.

Меню слева идёт без подписей групп: группы разделены тонкими линиями и должны влезать без прокрутки при высоте окна от 760 px. Сверху окна — только логотип, поиск (Ctrl+K) и кнопки окна.

## 8. Мониторинг
_Детали API — по итогам `docs/research/lowlevel-monitoring-interrupts.md`._ Принципы:
- ETW-сессия ядра (DPC, ISR, загрузка образов) в фоновом потоке. Агрегация по модулям без аллокаций на событие. Раз в секунду считается срез: максимум и среднее за секунду по модулю, гистограмма.
- PDH-счётчики добавляются по английским именам (система русская): % Interrupt Time, % DPC Time, загрузка и частота ядер, page faults, задержка диска.
- Поток данных в интерфейс — `monitor.tick` 2 раза в секунду, только пока раздел открыт.
- Сессия ETW всегда останавливается при выходе, в том числе при падении (обработчик выхода плюс остановка «зависшей» сессии с нашим именем при следующем старте).
- Шкала оценки по худшему DPC/ISR за окно: < 100 мкс — «Отлично», < 250 — «Хорошо», < 500 — «Норма», < 1000 — «Плохо», ≥ 1000 — «Критично». Балл 0–100 — монотонная функция от p99 и максимума.

## 9. Пресеты
- Встроенные:
  - «Игровой» — все `proven` с `risk: low`;
  - «Игровой+» — плюс `situational`, подходящие под это железо, с подтверждением;
  - «Приватность».
- Свой пресет — это набор `{tweakId, value?}` плюс динамические настройки (MSI/affinity по устройствам с привязкой к Hardware ID, IFEO, параметры схемы питания). Экспорт и импорт — файл `.hateeze.json` со схемой и версией.
- При импорте показывается предпросмотр: что изменится, что не подходит к этому ПК (нет устройства, другой вендор GPU), что отклонено (запрещённые цели, неизвестные id).

- **Палитра — серебро на тёмном:**
  - фон `#060708` с мягким градиентом `#101216` сверху;

  - серебро `#f4f6fa` / `#c9ced8` / `#8e95a3`, сталь `#6b7384`;

  - график: DPC — светлое серебро со свечением, ISR — сталь `#7d8799`.
- **Радиусы:** панели 20 px, кнопки 12 px.
- **Шрифты:** Segoe UI Variable (системный); моноширинный JetBrains Mono (woff2 в ресурсах, OFL), запасной — Cascadia Mono.

## 12. Обработка ошибок
- Любая ошибка ядра попадает в интерфейс как тост с русским текстом и кнопкой «подробнее» (детали из лога).
- Частичный успех (часть твиков применилась) показывается списком с причиной по каждому пункту.
- Загрузки: повтор с докачкой (Range), таймауты, понятная ошибка «сайт недоступен» с предложением запасного пути (winget / зеркало).
- Нет прав на ключ реестра — понятное сообщение; обход защиты TrustedInstaller не делаем.
- Падение приложения: глобальный обработчик пишет лог и останавливает ETW-сессию.

## 13. Тестирование
- **Юнит-тесты Core (xUnit) на поддельных платформенных сервисах:**
  - каталог: каждый файл валиден; id уникальны; у каждого не-avoid твика есть revert; типы значений корректны; `{{value}}` только у value/select; ни одна цель не входит в запрещённый список;
  - движок: применение → проверка → откат возвращает исходное состояние байт в байт; «Вернуть всё» в обратном порядке; ошибка в середине откатывает уже сделанное;
  - журнал и снимок: запись, чтение, восстановление после «обрыва» файла;
  - мост: маршрутизация, ошибки, отмена операций;
  - установщики: разбор ответов API драйверов (фикстуры JSON), патчер setup.cfg NVIDIA на фикстуре, выбор ссылок приложений, сравнение версий;
  - пресеты: импорт с неизвестными и запрещёнными целями.
- **Интерфейс:** `tsc --noEmit`, eslint, сборка Vite; просмотр всех разделов в браузере на моках (скриншоты).
- **Проверка на этой машине — только чтение:** запуск exe, мониторинг ETW/PDH, перечисление устройств, схем питания, служб, задач; поиск драйвера NVIDIA для RTX 4060 (без установки). Применение твиков и установку драйверов на машине разработчика не выполняем — это ручная проверка пользователя (лучше на виртуальной машине или после точки восстановления).

## 14. Сборка и поставка
- `build.ps1`: `npm ci && npm run build` в `web/` → `dotnet test` → `dotnet publish src/Hateeze.App -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true` → `dist/hateeze.exe` + `hateeze.exe.sha256`.
- Манифест: `requireAdministrator`, PerMonitorV2, supportedOS Win10.
- Иконка и логотип: стеклянная капля с буквой «h» (как в макете).
